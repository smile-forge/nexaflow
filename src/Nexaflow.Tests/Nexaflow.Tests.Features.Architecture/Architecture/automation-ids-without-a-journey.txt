# AutomationIds that no UI journey names yet — the ratchet for AutomationIdJourneyCoverageTests.
#
# Every line here is a view element that was given a stable automation id and then never clicked by a
# test. This file exists so the rule could be turned on against a repo that already had a backlog; it
# is not an allowlist. Adding a line is a deliberate admission, and the guard tests keep it honest in
# both directions: a NEW unreferenced id fails until it is either covered or listed here, and a line
# that has since been covered — or whose id no view declares any more — fails until it is deleted.
#
# So the right move on seeing an id here is to write the journey that clicks it and remove the line.

# src/Nexaflow.Features/Nexaflow.Features.WindowsFileSystem/Views/FileOperationsPanel.xaml
# Renders only inside the row template of a FAILED operation. Reaching it means making a real copy fail
# mid-flight — a denied destination, or a source pulled away under the engine — which is a journey about
# failure handling rather than one that happens to press a button, and is worth writing as its own.
FileOps_Retry
# The dismiss cross shares that row: its Visibility is bound to HasProblems, so it too needs a failure
# to exist at all. Its sibling on the same cell, FileOps_CancelRow, is the mutually exclusive CanCancel
# one and is already driven by FileOperationsPanelJourneyTests.
FileOps_DismissRow
# And the paused row's Stop needs something further still: IsPaused is only set when a copy stopped
# because the destination volume ran out of space. A journey cannot fill a disk.
FileOps_StopPaused
