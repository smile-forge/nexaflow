# Where the reading parts from Markdig, and why — a ratchet: MarkdownDifferentialTests fails on a divergence this does
# not hold and on a line here that no longer diverges. One line per divergence, as the test writes it: the document, the
# side that said it, and the construct by what it is and the characters it stands for. Each group under a line saying why.

# Markdig reads a heading underlined over several lines as one run of text, the line ending a character of it; the
# reading holds the soft break CommonMark says it is. The specification's HTML is the same either way.

# Markdig keeps a definition's address as written, entities and all, and reads them only where a link takes it up; the
# reading says where the definition goes. The links themselves agree.
CommonMark#33	markdig-only	reference[to=/f&ouml;&ouml;] "[foo]: /f&ouml;&ouml; "f&ouml;&ouml;""
CommonMark#33	today-only	reference[to=/föö] "[foo]: /f&ouml;&ouml; "f&ouml;&ouml;""

# Markdig's span for a definition takes in a title on the next line that it then refused, and starts the paragraph
# after it. The specification's HTML agrees with the reading: Markdig is the one wrong here.
CommonMark#210	markdig-only	reference[to=/url] "[foo]: /url\n"title""
CommonMark#210	markdig-only	paragraph "ok"
CommonMark#210	today-only	reference[to=/url] "[foo]: /url"
CommonMark#210	today-only	paragraph ""title" ok"

# A definition with no term of its own — a second ":" under the first — read alone is a paragraph: MarkdownBlocks reads

DefinitionListSpecs#1	today-only	paragraph ":   This ia another definition item"
