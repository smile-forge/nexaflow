USB device

One USB device on its own page: what it is, what you can do with it now, what it is made of, and what is wrong with it.

Getting here

  • On the USB page, select a device (or anything inside one) and choose Open device.
  • Show in USB tree goes back to the device's place on the USB page.
  • The page follows the device, not the port: unplug it and the page says so and stops its tools; plug it back in — the same port or another — and it picks it up again.
  • A drive Windows has ejected (“Safe to remove”) is still in its port but no longer in use: the page says it is ejected, and its tools come back when it is plugged in again.

Overview

  • What the device is, in plain words, and its identity, connection, power and driver facts. Show me

Live tools

  • Each thing the device can do gets a tile: open it to use it, shut it to stop what is live in it. Tiles sit side by side when the window is wide enough. Show me
  • Mass storage browses the device's volumes as the file browser browses a disk: a folder tree beside the open folder, a path bar, sortable columns, and right-click menus with Copy path. Double-click or Enter opens a folder, or a file in its viewer; Backspace goes up; F2 renames; Delete deletes. Show me
  • Copy files and folders to this PC, or onto the device — with Add files (one or several), Add folder, or by dragging them in. Every copy is read back from where it landed and checked against the original's SHA-256, and a copy that does not match is removed. Copying onto the device, renaming and deleting each ask first.
  • Phone files browses what a phone or camera shares over MTP — its internal storage, an SD card — in the same way, with the same checked copies. A file on the phone is fetched to this PC and checked before it opens. A locked phone shares nothing: unlock it and choose File transfer in its USB settings, and its storage shows here as soon as it does.
  • Audio output plays a tone, a 20 Hz – 20 kHz sweep or a WAV file on every channel or one, at a level you set. Identify channels sounds each channel in turn and names it as it plays.
  • Audio input meters every channel live, and Record… saves a few seconds to a WAV exactly as the device sent it.
  • HID shows each collection's report layout as the HID class driver decoded it, watches its input live, and reads and sends feature and output reports. Sending a report asks first. Windows keeps keyboards and mice to itself, so their input cannot be watched here; their layout and feature reports can.
  • Serial port names the COM port of a serial device — or of a phone's modem — and opens the serial terminal on it.
  • Anything on the device no tool covers is listed last, with what it is and what a tool for it would use.

Interfaces

  • The device's configurations, interface associations, interfaces and endpoints, each with its facts — the Windows function that owns it and that function's driver — and its descriptor field by field beside its bytes. Show me

Diagnostics

  • Problems Windows or the descriptors report: problem codes in plain words, descriptors that do not add up, strings the device did not answer for. Show me
  • Everything the live tools did — copies, recordings, reports sent — with the time. Show me
  • Read device again asks the device for its descriptors and strings, waking it if it slept.
  • Copy or save the device's debug details for the Nexaflow developers: its descriptors raw, what Windows made of it, its HID report descriptors, what each live tool sees, and what they did. Send them when a device does not work as it should. Serial numbers and volume labels are left out.

Asking the assistant

  • The assistant sees the device and every live tool's state. It can run any tool's read-only operations by itself — list a folder, read a feature report, read the audio levels — and, with your approval each time, the ones that act: copying, playing, recording, sending a report.
